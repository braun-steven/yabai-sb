Name
----

yabai - window manager

Synopsis
--------

*yabai* [*--load-sa*|*--uninstall-sa*|*--install-service*|*--uninstall-service*|*--start-service*|*--restart-service*|*--stop-service*|*--message*,*-m* 'msg'|*--version*,*-v*|*--help*,*-h*|*--generate-completion-script* 'shell'|*--check-config* ['config_file']|[*--config*,*-c* 'config_file'] [*--verbose*,*-V*]]

Description
-----------

*yabai* is a tiling window manager for macOS based on binary space partitioning.

Options
-------
The actions (*--load-sa* through *--stop-service*), *--message*, *--version*, *--help*, *--generate-completion-script* and *--check-config*
must be given alone. Option values may also be attached, e.g. *--config=*'<config_file>'.

*--load-sa*::
    Load the scripting-addition into Dock.app. +
    Installs and updates the scripting-addition when necessary. +
    Path is /Library/ScriptingAdditions/yabai.osax. +
    System Integrity Protection must be partially disabled.

*--uninstall-sa*::
    Uninstall the scripting-addition. Must be run as root. +
    Path is /Library/ScriptingAdditions/yabai.osax. +
    System Integrity Protection must be partially disabled.

*--install-service*::
    Writes a launchd service file to disk. +
    Path is ~/Library/LaunchAgents/com.braun-steven.yabai-sb.plist.

*--uninstall-service*::
    Removes a launchd service file from disk. +
    Path is ~/Library/LaunchAgents/com.braun-steven.yabai-sb.plist.

*--start-service*::
    Enables, loads, and starts the launchd service. +
    Will install service file if it does not exist.

*--restart-service*::
    Attempts to restart the service instance.

*--stop-service*::
    Stops a running instance of the service and unloads it.

*--message*, *-m* '<msg>'::
    Send message to a running instance of yabai. +
    The response is awaited for 30 seconds by default; set *YABAI_CLIENT_TIMEOUT* to a positive number of seconds to change it, other values are ignored. +
    A message longer than 1 MiB, or one that does not arrive complete, is answered with `invalid message`.
    `yabai -m batch` runs several commands from stdin in one message; see *Batch* under Domains. `yabai -m subscribe` streams events to the client; see *Subscribe* under Domains.

*--config*, *-c* '<config_file>'::
    Use the specified *yabai.toml* instead of the one the daemon searches for (see CONFIGURATION).

*--check-config* ['<config_file>']::
    Check a *yabai.toml* and exit, without a daemon: the report of *yabai -m config --check* for <config_file>, or else for
    the file the daemon loads (see CONFIGURATION). The exit status is 0 when there is no failure, and 1 otherwise. +
    `yabai --check-config ~/.config/yabai/yabai.toml`

*--verbose*, *-V*::
    Output debug information to stdout. +
    Each line has a timestamp, a level and a component, e.g. `2026-10-20 14:03:12.345 debug yabai.event: window moved: Safari 1234`. +
    Levels up to 'notice' go to stdout, 'warning' and above to stderr.

*--version*, *-v*::
    Print version to stdout and exit.

*--help*, *-h*::
    Print options to stdout and exit.

*--generate-completion-script* '<shell>'::
    Print a completion script for 'zsh', 'bash' or 'fish' to stdout and exit, e.g. +
    `yabai --generate-completion-script zsh > "${fpath[1]}/_yabai"`.

Configuration
-------------

The daemon reads *yabai.toml* at startup, before it adopts the windows of the session, and applies it in-process, so its settings, space labels, rules and signals are in place for the windows that are already open. The file is the one given with *--config*; otherwise it is the first existing file of `$XDG_CONFIG_HOME/yabai/yabai.toml` (only when *XDG_CONFIG_HOME* is set and not empty) and `~/.config/yabai/yabai.toml` (see *Files*). A file with an error is not applied: the daemon starts with the defaults, logs each error and sends a notification.

The whole file is checked before anything is applied, and checking changes nothing: `yabai --check-config [<config_file>]` checks a file without a daemon, and *yabai -m config --check* checks the file of the running daemon. Each error is reported with its file, line and key.

The file is applied again without a restart by *yabai -m config --reload*, and by the daemon when the file is saved, if *auto_reload* is on (see below). A reload runs only the settings whose value differs from the running state, so a reload of an unchanged file changes nothing. A value set at runtime with *yabai -m config*, *rule* or *signal* is an override: it lasts until the next reload or restart, which puts the file's value back, and *config --overrides* lists the overrides. A value that should last belongs in the file.

After each applied file, at startup and after each reload, the signal event *config_loaded* fires (see *Signal*), so a signal with `event = "config_loaded"` runs once the settings are in effect. It does not fire for a file with an error.

The file has these tables. Unknown tables and keys, and a value of the wrong kind, are errors, so a misspelled option is reported rather than ignored.

`[daemon]`::
    `auto_reload = true|false` (default `true`): the daemon watches the directory of *yabai.toml* (and, when it is a symlink, the directory of its target) and reloads the file when it is saved, as *config --reload* does, so a change applies without a restart. A save that leaves the text unchanged changes nothing. A save of a file with an error keeps the running config: the errors are logged, and a notification names the file and their number. The watch is also on when the file was not valid at startup, so fixing it applies it. `auto_reload = false` turns the watch off; *config --reload* still works. A reload that changes this value starts or stops the watch. `load_scripting_addition = true|false` (default `false`): the daemon loads the scripting addition itself, by running `sudo -n <path of yabai> --load-sa` (the path it was started from, with links kept) at startup, after each Dock restart, and when a reload turns this setting on (a reload that turns it off does nothing). The load runs in a child process, so the daemon does not wait for it. A failed load is notified, and it needs the sudoers setup below.

Sudoers setup: the load runs `sudo -n` as your user, so your user needs a sudoers entry that runs the binary as root without a password. As root, run `sudo visudo -f /private/etc/sudoers.d/yabai` and add this line, with your user name for `<user>` and the path of the binary for `<path>`:

----
<user> ALL=(root) NOPASSWD: sha256:<digest> <path> --load-sa
----

`<path>` is the path yabai is started from (`which yabai`), e.g. the link `/opt/homebrew/bin/yabai` of a Homebrew install, since the daemon runs the binary at that path. `<digest>` is the SHA-256 of the file it points to (`shasum -a 256 <path>`). The digest changes with each build, so update the line after an upgrade. Without the entry the load fails with `sudo: a password is required`.

`[config]`::
    One key for each option of *config*, under the option's name, e.g. `window_gap = 10`. A boolean option takes `true` or `false`, and an option with more choices also takes its words, e.g. `window_shadow = "float"`. A color is an integer, e.g. `active_window_border_color = 0xff51afef`, or a string: the same hex digits (`"0xff51afef"`), `rgb(r, g, b)` or `rgba(r, g, b, a)` with r, g and b from 0 to 255 and a from 0 to 1, e.g. `"rgba(81, 175, 239, 0.8)"`. An option that takes a number takes a TOML integer or float, e.g. `window_gap = 10`. Every other option takes the string that its command takes, e.g. `scratchpad_grid = "40:40:1:1:38:38"`. `space_layout` is an array of layouts, e.g. `space_layout = ["15", "10:5"]`; an empty array turns it off.

`[[space]]`::
    One table for each space that has a label, a pin or its own options. `index` names the space by its Mission Control index (required, at least 1, and once per space). `label` and `pin` are those of *space --label* and *space --pin*. The other keys are the options that take *--space*: `top_padding`, `bottom_padding`, `left_padding`, `right_padding`, `window_gap`, `layout` and `auto_padding`, e.g. `window_gap = 0`.

`[[rule]]`::
    One table for each rule, with the keys of *rule --add*, e.g. `app = "^Calendar$"` and `space = 9`. A flag takes `true` or `false` (the `on` and `off` of *rule --add*), e.g. `manage = false`. `one_shot = true|false` makes the rule one-shot (`--one-shot`). `app`, `title`, `role` and `subrole` can be negated with an inline table, e.g. `title = { not = "^(Copy|Move)$" }`.

`[[signal]]`::
    One table for each signal, with the keys of *signal --add*: `event` and `action` are required, e.g. `event = "window_focused"` and `action = "sketchybar --trigger window_focus"`. `label`, `app` and `title` (negated as in a rule) are optional, and `active = true|false` is the `yes` or `no` of *signal --add*.

The settings are applied in this order: the `[config]` options (*space_layout* after the others), then the `[[space]]` labels, pins and options, then the rules and the signals, each list in the order of the file, and *config_loaded* last. At startup the rules exist before the existing windows are adopted, so they apply to those windows too. A setting that fails while it is applied is logged: at startup a notification counts the failures, and the other settings are still applied.

Editors can check and complete the file with `doc/yabai.schema.json`, a JSON Schema of the keys above. It is the schema that Taplo and the Even Better TOML extension of VS Code read, and a test keeps it in step with the keys the daemon accepts. Point the editor at it with a `#:schema` line as the first line of the file: `#:schema ../doc/yabai.schema.json` in `examples/yabai.toml` (a relative path), or, for `~/.config/yabai/yabai.toml`, the URL `https://raw.githubusercontent.com/braun-steven/yabai-sb/main/doc/yabai.schema.json` (once it is on the fork's main branch), or the path of a local copy. The schema is an aid: the daemon checks the file itself, and an error is still reported by *--check-config*.

Definitions
-----------

[subs=+macros]
----
REGEX       := https://developer.apple.com/documentation/swift/regex[Swift Regex syntax], matched anywhere in the text; e.g. ^Safari$ or (?i)^settings

LABEL       := arbitrary string/text used as an identifier

LAYER       := below | normal | above | auto

BOOL_SEL    := on | off

FLOAT_SEL   := 0 < <value> <= 1.0

RULE_SEL    := <index> | LABEL

SIGNAL_SEL  := <index> | LABEL

DIR_SEL     := north | east | south | west

STACK_SEL   := stack.prev | stack.next | stack.first | stack.last | stack.recent | stack.<index (1-based)>

WINDOW_SEL  := prev | next | first | last | recent | mouse | largest | smallest | STACK_SEL | DIR_SEL | <window id> | LABEL

DISPLAY_SEL := prev | next | first | last | recent | mouse | DIR_SEL | <arrangement index (1-based)> | LABEL

SPACE_SEL   := prev | next | first | last | recent | mouse | <mission-control index (1-based)> | LABEL

EASING      := ease_in_sine  | ease_out_sine  | ease_in_out_sine  |
               ease_in_quad  | ease_out_quad  | ease_in_out_quad  |
               ease_in_cubic | ease_out_cubic | ease_in_out_cubic |
               ease_in_quart | ease_out_quart | ease_in_out_quart |
               ease_in_quint | ease_out_quint | ease_in_out_quint |
               ease_in_expo  | ease_out_expo  | ease_in_out_expo  |
               ease_in_circ  | ease_out_circ  | ease_in_out_circ
----

A `DIR_SEL` in a `DISPLAY_SEL` selects the nearest display in that direction. When there is none that way, it wraps around to the display lying farthest the other way, measured from the center of the acting display to the nearest point of each display, like sway's 'focus output <dir>' and 'move container|workspace to output <dir>': with three displays side by side, `east` from the eastmost one selects the westmost one. It fails only when no other display lies that way or wholly the other way. The directions of *window --focus* and *window --warp* (`WINDOW_SEL` and the tree) do not wrap to another display.

Domains

Config

General Syntax
^^^^^^^^^^^^^^

yabai -m config <global setting>::
    Get or set the value of <global setting>.

yabai -m config [--space '<SPACE_SEL>'] <space setting>::
    Get or set the value of <space setting>.

Check the Config File
^^^^^^^^^^^^^^^^^^^^^

yabai -m config --check ['<config_file>']::
    Check a `yabai.toml` file without applying it. Without <config_file>, check the file the daemon loads: the one given with *--config*, or else the first existing file of `$XDG_CONFIG_HOME/yabai/yabai.toml` and `~/.config/yabai/yabai.toml`. A relative <config_file> is resolved in the directory of the `yabai -m` command. +
    The whole file is decoded first, and every unknown key or wrong kind of value is a failure. Then each setting is lowered to the `yabai -m` message that the daemon would run for it, and that message is checked as the daemon checks it. Nothing is applied: the check runs no command and changes no setting. The domains *space*, *display*, *window* and *query* act on the session, so a `[[space]]` label or pin is reported as not checked. +
    The output has one line per failure, `<file>:<line>: <key path>: <message>`, one `note: <file>:<line>: <key path>: not checked: <reason>` line per setting that is not checked, and the summary `checked N settings, M failures`, with `, K not checked` when K is not zero. A file that does not decode is reported line by line, and nothing is checked. +
    The exit status is 0 when there is no failure. It is 1 when there is a failure, and when the file cannot be read or found; the failures are then printed on stderr.

yabai --check-config ['<config_file>']::
    Check a `yabai.toml` file as *yabai -m config --check* does, without a running daemon, and exit. Without <config_file>, check the file the daemon loads. The report goes to stdout, or to stderr when there is a failure, and the exit status is 0 only when there is no failure. The check does not change anything and needs no window server, e.g. `yabai --check-config ~/.config/yabai/yabai.toml`.

Reload the Config File
^^^^^^^^^^^^^^^^^^^^^^

yabai -m config --reload ['<config_file>']::
    Reload the *yabai.toml* that the daemon loads, without restarting it. Without <config_file>, reload the file that *config --check* checks: the one given with *--config*, or else the first existing file of `$XDG_CONFIG_HOME/yabai/yabai.toml` and `~/.config/yabai/yabai.toml`. A relative <config_file> is resolved in the directory of the `yabai -m` command. +
    The file is decoded and checked as *config --check* checks it. When the check reports a failure, the report is printed as a failure and nothing changes. Otherwise the daemon compares each setting with its running value, in the order of the startup (the global options, *space_layout*, the space labels, pins and per-space options, then the rules and signals), and runs only the settings that differ. A reload of an unchanged file changes nothing, and the windows, trees and spaces stay as they are. +
    A setting that the file no longer sets goes back to its default, and a space label or pin that the file no longer sets is removed. A rule or signal list that differs from the file's is replaced, and a rule applies to windows created after the reload. The reply is `reloaded <config_file>: <n> changes`, where <n> counts the messages that ran without a failure, the per-space values that were reset and the rule and signal lists that were replaced. A setting can still fail while it runs, for example a rule whose *space* names no existing space: the other settings still run, each failure is logged, and the reply is a failure, `reloaded <config_file>: <n> changes, <m> failures` followed by a `<key path>: <message>` line for each. A one-shot rule of the file is removed once it matched a window, as any one-shot rule is; a reload adds it again only when the file's one-shot rules change. +
    A value set with *yabai -m config* lasts until the next reload or restart (see *config --overrides*). An skhd binding can run `yabai -m config --reload`.

yabai -m config --overrides::
    List the overrides: the settings whose running value differs from the file. Each is one line, `<option> <running value> (file: <value>)`, and a per-space setting is `space <index> <option> <running value> (file: <value>)`. A rule or signal list that differs from the file's is printed as `rules: overridden` or `signals: overridden`. The file's value is the one the file sets, or the default of the setting when it does not set it; with no file loaded, the defaults are the file's values. Nothing is printed when nothing is overridden. The command takes no argument and changes nothing.

yabai -m config --dump::
    Print the running config as a *yabai.toml* to stdout: the `[daemon]` table, every `[config]` option with its running value, a `[[space]]` table for each space that has a label, a pin or a per-space setting, and the `[[rule]]` and `[[signal]]` tables. A line gets `# override` when its value is not the one the file gives (as *config --overrides* decides), and `# default` when its value is the default of the setting. The text checks clean with *config --check*, and reads back as the settings it was written from, so it can be saved as a file to start from. A space is written by its Mission Control index, which needs the spaces of the window server, and a pin by its display's index. The command takes no argument and changes nothing.

Global Settings
^^^^^^^^^^^^^^^

*debug_output* ['<BOOL_SEL>']::
    Enable output of debug information to stdout.

*external_bar* ['<main|all|off>:<top_padding>:<bottom_padding>']::
    Specify top and bottom padding for a potential custom bar that you may be running. +
    'main': Apply the given padding only to spaces located on the main display. +
    'all':  Apply the given padding to all spaces regardless of their display. +
    'off':  Do not apply any special padding.

*menubar_opacity* ['<FLOAT_SEL>']::
    Changes the transparency of the macOS menubar. +
    If the value is 0.0, the menubar will no longer respond to mouse-events, effectively hiding the menubar permanently. +
    The menubar will automatically become fully opaque upon entering a native-fullscreen space, and adjusted down afterwards.

*mouse_follows_focus* ['<BOOL_SEL>']::
    When focus goes to another display than the one under the mouse, put the mouse at the center of the focused window, or at the center of the display when it has no window to focus, like sway's 'mouse_warping output'. Focus that stays on the display under the mouse never moves it. +
    The commands that move a window (*window --warp*, *--swap*, *--display* and *--space*) do not move the mouse, also when the moved window keeps focus on another display. +
    Unlike upstream yabai, focusing a window on the display under the mouse no longer puts the mouse at its center.

*focus_follows_mouse* ['autofocus|autoraise|off']::
    Automatically focus the window under the mouse. +
    When the mouse moves onto the desktop or a gap of a display without focus, focus goes to that display, like sway: to the window focused last on its space ('autofocus' does not raise it, 'autoraise' does), or to the display itself when the space has no window to focus, through a click on the desktop under the mouse. This happens once each time focus is on another display than the one under the mouse; the desktop of the focused display, the menu bar and the Dock do not move focus. The mouse is never moved, also with *mouse_follows_focus* on.

*display_arrangement_order* ['default|vertical|horizontal']::
    Specify how displays are ordered (determined by center point). +
    'default': Native macOS ordering. +
    'vertical': Order by y-coordinate (followed by x-coordinate when equal). +
    'horizontal': Order by x-coordinate (followed by y-coordinate when equal).

*space_layout* ['<LAYOUT> [<LAYOUT> ...]|off']::
    Keep a fixed number of spaces on each display. +
    '<LAYOUT>' is a colon-separated list of space counts, one entry per display in arrangement order, e.g. '10:5'. +
    Give one '<LAYOUT>' per number of connected displays; the layout whose entry count matches the number of active displays is used, e.g. '15 10:5 10:5:1b'. +
    An entry suffixed with 'b' belongs to the built-in display, and the remaining entries apply to the other displays in order. +
    After displays are added, removed or moved, and after spaces are created or destroyed, spaces are moved between displays, created or destroyed until every display matches its target. +
    Spaces that contain windows are never destroyed. Spaces pinned to a connected display (see *--pin*) are never moved or destroyed by this. +
    Like sway's output priority, a space whose display goes away remembers that display, and when the display is connected again, the spaces that came from it return to it first, as many as its target takes; the rest of its target is filled from the displays with too many spaces. A pin wins over the remembered display. The remembered displays are kept until the daemon quits. +
    A pinned space counts towards the target of its display: when a pin brings a space to a display that already has its target, another unpinned space leaves that display, the visible one when no other is left. +
    System Integrity Protection must be partially disabled.

*builtin_display_last* ['<BOOL_SEL>']::
    Order the built-in display after all other displays. +
    This affects both display indices and space indices, e.g. with two external displays holding 15 spaces, the space of the built-in display becomes space 16.

*window_origin_display* ['default|focused|cursor']::
    Specify which display a newly created window should be managed in. +
    'default': The display in which the window is created (standard macOS behaviour). +
    'focused': The display that has focus when the window is created. +
    'cursor': The display that currently holds the mouse cursor.

*skip_window_focus_animation* ['<BOOL_SEL>']::
    Bypass macOS space animation when an application or window on an inactive space is focused. +
    You should only enable this if you do NOT use the scripting addition. +
    The scripting addition implements the same functionality in a more robust way.

*space_auto_back_and_forth* ['<BOOL_SEL>']::
    Like sway's 'workspace_auto_back_and_forth': *space --focus* with the mission-control index or the label of the focused space focuses the recent space instead, which can be on another display. +
    Only an index or a label goes back; 'prev', 'next', 'first', 'last', 'recent' and 'mouse' are unchanged, as sway applies it to 'workspace <name>' and 'workspace number <n>' only. +
    Without a recent space the command fails as before. Default is 'off'.

*window_shadow* ['<BOOL_SEL>|float']::
    Draw shadow for windows. +
    System Integrity Protection must be partially disabled.

*window_opacity* ['<BOOL_SEL>']::
    Enable opacity for windows. +
    System Integrity Protection must be partially disabled.

*window_opacity_duration* ['<FLOAT_SEL>']::
    Duration of transition between active / normal opacity. +
    System Integrity Protection must be partially disabled.

*active_window_opacity* ['<FLOAT_SEL>']::
    Opacity of the focused window. +
    System Integrity Protection must be partially disabled.

*normal_window_opacity* ['<FLOAT_SEL>']::
    Opacity of an unfocused window. +
    System Integrity Protection must be partially disabled.

*window_animation_duration* ['<FLOAT_SEL>']::
    Duration of window frame animation. +
    If 0.0, the change in dimension is not animated. +
    Requires Screen Recording permissions. +
    System Integrity Protection must be partially disabled.

*window_animation_easing* ['<EASING>']::
    Easing function to use for window animations. +
    See https://easings.net for details.

*insert_feedback_color* ['0xAARRGGBB']::
    Color of the *window --insert* message and mouse_drag selection. +
    The purpose is to provide a visual preview of the new window frame.

*window_border* ['<BOOL_SEL>']::
    Draw a border around each window, in the active color for the focused window and in the normal color otherwise. +
    The border sits outside the window frame and is ordered right below the window. It is shown for standard windows,
    and hidden while a window is minimized, hidden, in native fullscreen or animated. +
    The border of the active tab of a tabbed container goes around the whole container, tab bar and backdrop card
    included; windows of hidden tabs have no border.

*window_border_hide_single* ['<BOOL_SEL>']::
    Hide the border while a tiled window is alone on its space. Count the visible windows of each active tab,
    including windows in splits; hidden tabs and scratchpads do not count. Floating windows always retain their borders.

*window_border_width* ['<FLOAT_SEL>']::
    Width of the window border in points.

*active_window_border_color* ['0xAARRGGBB']::
    Color of the border of the focused window.

*normal_window_border_color* ['0xAARRGGBB']::
    Color of the border of every other window.

*tab_bar* ['<BOOL_SEL>']::
    Draw a tab bar on top of every tabbed container, like the tabbed layout of i3. Enabled by default. +
    Each tab shows the title of a window, and clicking a tab focuses that window. +
    The windows of the container are shrunk by *tab_bar_height* to make room for the bar.

*tab_bar_height* ['<integer number>']::
    Height of the tab bar in points. Default is 24.

*tab_bar_offset* ['<integer number>']::
    Space in points between the bottom of the tab bar and the windows of the container, inside the backdrop card if there is one. Default is 0. +
    A negative value moves the windows up under the bar. The windows always keep at least *tab_bar_height* of height.

*tab_bar_backdrop* ['off|glass|blur']::
    Backdrop card of the 'glass' tab bar style. Default is 'blur'. +
    The card is a rounded surface behind the whole tabbed container that holds the bar at its top and the active window below it, so the wallpaper never shows between the bar and the window. +
    The card hides the other windows of the container. The bar keeps its Liquid Glass track, tinted with *tab_bar_unfocused_color*, on top of the card. +
    'blur' uses the native material for backgrounds beneath windows, with a neutral color that follows *tab_bar_appearance*. 'glass' draws the whole card in Liquid Glass, and 'off' draws no card, so the bar floats above the windows in its own track. +
    Cards have a subtle outline that becomes stronger with Increase Contrast. The card is never drawn for the 'i3' style.

*tab_bar_backdrop_color* ['0xAARRGGBB']::
    Optional tint of the backdrop card. The 'blur' backdrop uses its native material color until this option is configured. +
    The default value '0xff48484a' is used with 40% opacity for the 'glass' backdrop in dark appearance; system appearance uses an adaptive default tint. A configured color is used as given for either backdrop. Reduce Transparency makes the backing opaque.

*tab_bar_card_padding* ['<integer number>']::
    Space in points between the edges of the backdrop card and the tab bar and windows inside it. Default is 6.

*tab_bar_window_radius* ['<integer number>']::
    Corner radius in points that windows are assumed to have. Default is 16. +
    The backdrop card is rounded with this radius plus *tab_bar_card_padding*, so its corners are concentric with the corners of the window inside it. +
    Windows with a toolbar have a larger radius in macOS 26 (about 26).

*tab_bar_style* ['glass|i3']::
    Look of the tab bar. Default is 'glass'. +
    'glass' draws the window tabs in the Liquid Glass material of macOS 26: the tabs sit in a translucent rounded track tinted with the unfocused color, and the active tab is a glass pill tinted with the focused or inactive color that slides to the new tab on a switch. +
    The bar uses dark glass by default; *tab_bar_appearance* can follow the system appearance instead. A *tab_bar_\*_color* background color that was not configured is applied with reduced opacity in 'glass' (40% for the track, 80% for the pill), so the glass stays visible. A configured color is used as given, except that Reduce Transparency makes the backing tints opaque. +
    Glass tabs use native AppKit buttons with hover and press feedback and accessible titles and selection state. Default text colors adapt to the appearance; configured text colors override them. Reduce Motion disables transitions, and Increase Contrast adds outlines and stronger default text. +
    'i3' draws flat tabs side by side in the *tab_bar_\*_color* colors.

*tab_bar_appearance* ['dark|system']::
    Appearance of glass tab bars. Default is 'dark', including when macOS uses light mode. +
    'system' follows the macOS appearance for the controls and backdrop, with adaptive default materials and glass tints. Configured background and text colors are retained. This option does not affect the 'i3' style.

*tab_bar_font* ['<family>:<size>']::
    Font of the tab titles, e.g. 'Menlo:12'. The family 'system' selects the macOS system font. Default is 'system:12'.

*tab_bar_icons* ['<BOOL_SEL>']::
    Draw the application icon left of the title in each window tab. Enabled by default. +
    Tabs that hold a nested container show only the title.

*tab_bar_focused_color* ['0xAARRGGBB'], *tab_bar_focused_text_color* ['0xAARRGGBB']::
    Background and text color of the active tab of the tabbed container that holds the focused window.

*tab_bar_inactive_color* ['0xAARRGGBB'], *tab_bar_inactive_text_color* ['0xAARRGGBB']::
    Background and text color of the active tab of every other tabbed container.

*tab_bar_unfocused_color* ['0xAARRGGBB'], *tab_bar_unfocused_text_color* ['0xAARRGGBB']::
    Background and text color of the tabs that are not active.

*scratchpad_exclusive* ['<BOOL_SEL>']::
    Keep at most one scratchpad window shown. +
    When *window --toggle* '<LABEL>' shows or focuses a scratchpad, every other scratchpad window that is shown, on any space or display, is hidden. +
    Hiding a scratchpad does not show the one that was hidden before it. +
    System Integrity Protection must be partially disabled.

*scratchpad_raise* ['<BOOL_SEL>']::
    When *window --toggle* '<LABEL>' acts on a scratchpad that is shown on the active space but does not have focus, focus and raise it instead of hiding it. +
    The scratchpad is only hidden if it already has focus.

*scratchpad_below* ['<BOOL_SEL>']::
    Put scratchpad windows on the same stacking sub-layer as tiled windows instead of above them, so focusing a tiled window brings it in front of a shown scratchpad. +
    Does not affect a scratchpad whose sub-layer was set with *window --sub-layer*. +
    System Integrity Protection must be partially disabled.

*scratchpad_grid* ['<rows>:<cols>:<start-x>:<start-y>:<width>:<height>|off']::
    Set the frame of a scratchpad window, as with *window --grid*, each time *window --toggle* '<LABEL>' shows it while it was hidden. +
    A scratchpad that is already shown, on this or another space, keeps its frame when it is focused or moved to the active space.

*mouse_modifier* ['cmd|alt|shift|ctrl|fn']::
    Keyboard modifier used for moving and resizing windows.

*mouse_action1* ['move|resize']::
    Action performed when pressing 'mouse_modifier' + 'button1'.

*mouse_action2* ['move|resize']::
    Action performed when pressing 'mouse_modifier' + 'button2'.

*focus_wrapping* ['on|off|force']::
    What *window --focus* 'north|east|south|west' does at the edge of a 'tree' space, like i3's 'focus_wrapping'. +
    'on' (the default): focus the display in that direction, and wrap around to the other side of the container if there is none. +
    'off': focus the display in that direction, and do nothing if there is none. +
    'force': always wrap around inside the innermost container in that direction.

*mouse_drop_action* ['swap|stack']::
    Action performed when a managed window is dropped in the center of some other managed window: swap the two windows, or make the dropped window a tab of the other one.

*mouse_drop_preview* ['outline|ghost']::
    What a managed window dragged over another managed window shows where it would be dropped. 'outline' (the default) outlines the half or the whole window. +
    'ghost' also shows a translucent copy of the dragged window in that area, scaled to fit, and for a swap a copy of the other window in the dragged window's own place. The copies are taken once per drag and freed when the drag ends.

*mouse_drag_split* ['on|off']::
    Dragging with the left button, without the 'mouse_modifier' key, on the gap between two tiled windows resizes their split: the gap follows the pointer, and each child keeps its minimum share. +
    A click inside a window, or on a floating window or menu over the gap, is passed on as before. The default is 'off'.

Space Settings
^^^^^^^^^^^^^^

*layout* ['tree|float']::
    Set the layout of the selected space. +
    'tree' (the default) arranges windows in an i3-style container tree, see *TREE LAYOUT*. 'float' leaves windows unmanaged. +
    A space that already has the layout keeps its windows and tree.

*tree_default_orientation* ['horizontal|vertical|auto']::
    Orientation of an empty 'tree' space when its first window opens, like i3's 'default_orientation'. +
    'horizontal' places windows side by side, 'vertical' places them on top of each other, and 'auto' (the default) picks 'horizontal' when the display is wider than it is tall.

*tree_workspace_layout* ['default|tabbed']::
    Like i3's 'workspace_layout'. With 'tabbed', a window or container that is placed directly on a 'tree' space opens inside a new tabbed container, so later windows next to it become tabs. This applies to the first window of an empty space, to a window that opens while the space itself is selected, and to a window that moves out of its container onto the space. Default is 'default'.

*tree_autotiling* ['<BOOL_SEL>']::
    Like the i3 autotiling script: a new window that opens next to a window splits that window along its longer side, so the space is divided like a binary tree. +
    Windows that open in a tabbed container, next to a selected container or with *window --insert* are placed as usual. Default is 'off'.

*top_padding* ['<integer number>']::
    Padding added at the upper side of the selected space.

*bottom_padding* ['<integer number>']::
    Padding added at the lower side of the selected space.

*left_padding* ['<integer number>']::
    Padding added at the left side of the selected space.

*right_padding* ['<integer number>']::
    Padding added at the right side of the selected space.

*window_gap* ['<integer number>']::
    Size of the gap that separates windows for the selected space.

*auto_padding* ['<BOOL_SEL>']::
    Remove padding on 'tree' spaces that hold at most one tiled container, so that it fills the whole area of the display (the menu bar, Dock and 'external_bar' are still respected). +
    The window gap is kept, so the windows of a split inside a single tabbed container stay apart. +
    The configured padding applies again as soon as the space holds two or more tiled containers. Padding and gap are always reported unchanged. +
    A tiled window is a managed window that is not floating, minimized or hidden, and not in zoom-fullscreen. Floating windows, including scratchpad windows and windows with the rule 'manage=off', never count. A tiled container is a tiled window, or a tabbed container holding at least one tiled window: a tabbed container counts once, however many tabs it holds. +
    Has no effect on spaces with layout 'float'. Padding toggled off with 'space --toggle' stays off regardless of the number of windows. +
    Windows placed with '--grid' always use the configured padding and gap, so their frame does not depend on the number of tiled windows.

Display
~~~~~~~

General Syntax
^^^^^^^^^^^^^^

yabai -m display ['<DISPLAY_SEL'>] '<COMMAND>'

COMMAND
^^^^^^^

*--focus* '<DISPLAY_SEL>'::
    Focus the given display. +
    Focus goes to a window zoomed to the whole space, else to the window focused last in the tree of its current space, like sway's 'focus output'. On a space without tiled windows it goes to the frontmost window yabai could manage there: windows on every space and system dialogs are skipped. A space with no such window focuses the display itself: yabai clicks its desktop (the centre, or another point when a window covers it; no click when every point is covered or the space is already focused), so Finder becomes the frontmost application. The cursor returns to where it was, or stays at the centre of the display with *mouse_follows_focus* on when it was on another display.

*--space* '<SPACE_SEL>'::
    The given space will become visible on the selected display, without changing focus. +
    The given space must belong to the selected display. +
    System Integrity Protection must be partially disabled.

*--label* ['<LABEL>']::
    Label the selected display, allowing that label to be used as an alias in commands that take a `DISPLAY_SEL` parameter. +
    If the command is called without an argument it will try to remove a previously assigned label.

Space
~~~~~

General Syntax
^^^^^^^^^^^^^^

yabai -m space ['<SPACE_SEL>'] '<COMMAND>'

COMMAND
^^^^^^^

*--focus* '<SPACE_SEL>'::
    Focus the given space. +
    Focus goes to the window that *display --focus* picks there, like sway's 'workspace': on the same display once macOS reports the switch, without moving the cursor. A space without such a window focuses no window. +
    With *space_auto_back_and_forth* on, the index or label of the focused space focuses the recent space instead.

*--switch* '<SPACE_SEL>'::
    The selected space will always be the currently focused space. +
    The given space substitutes the selected space, gaining focus. +
    If the selected space and the given space belong to different displays, this behaves like '--swap'. +
    If the selected space and the given space belong to the same display, this behaves like '--focus'. +
    System Integrity Protection must be partially disabled.

*--create*  ['<DISPLAY_SEL>']::
    Create a new space on the given display. +
    A direction, 'prev' and 'next' are measured from the display of a space selected by a 'SPACE_SEL', as for *--display*. +
    If none specified, use the display of the active space instead. +
    System Integrity Protection must be partially disabled.

*--destroy* ['<SPACE_SEL>']::
    Remove the given space. +
    If none specified, use the selected space instead. +
    System Integrity Protection must be partially disabled.

*--move* '<SPACE_SEL>'::
    Move position of the selected space to the position of the given space. +
    The selected space and given space must both belong to the same display. +
    System Integrity Protection must be partially disabled.

*--swap* '<SPACE_SEL>'::
    Swap the selected space with the given space. +
    If the selected space and given space belong to different displays, all the windows will swap. +
    If the selected space and given space belong to the same display, the actual spaces will swap. +
    System Integrity Protection must be partially disabled.

*--display* '<DISPLAY_SEL>'::
    Send the selected space to the given display. +
    A direction, 'prev' and 'next' are measured from the display of a space selected by a 'SPACE_SEL', like sway's 'move workspace to output <dir>', and from the active display for the active space. +
    Once macOS reports the move, the space is shown and focused there: the window focused last on it, or the display itself when the space is empty. The cursor moves only as *mouse_follows_focus* says. The moves of *--pin* and *space_layout* keep the focus. +
    System Integrity Protection must be partially disabled.

*--balance* ['x-axis|y-axis']::
    Give every child of every container on the selected space the same share of its container. +
    The axis is accepted for compatibility and ignored. *--equalize* is the same command.

*--mirror* 'x-axis|y-axis'::
    Flip the tree of the selected space along the given axis.

*--rotate* '90|180|270'::
    Rotate the tree of the selected space.

*--undo*::
    Restore the tree of the selected space as it was before its last change by a tree command: *--balance*, *--equalize*, *--mirror*, *--rotate*, *--restore-layout*, or a window's *--warp*, *--swap*, *--stack*, *--layout*, *--split*, *--ratio*, *--resize* or *--toggle split* that changed the tree. +
    The last 10 trees of each space are kept. Undo fails, and drops the kept trees of the space, when the windows of the space changed since it was recorded. Moving windows to another space or display and *--insert* are not undone.

*--save-layout* '<NAME>'::
    Write the tree of the selected space to `<NAME>.json` in `$XDG_CONFIG_HOME/yabai/layouts`, or `~/.config/yabai/layouts` when `XDG_CONFIG_HOME` is unset or empty, and print the path of the file. +
    NAME may contain only the characters `A-Z`, `a-z`, `0-9`, `.`, `_` and `-`, and may not be `.` or `..`. The directory is created when it is missing, and a file of the same name is replaced. +
    The file keeps the containers, shares, zoom and focus order of the tree, but not the selection. Each window is saved by its application (bundle id and name) and by its title, role and subrole at save time, not by its id. A window that yabai does not know is saved without that matcher. The file is JSON, version 1.

*--restore-layout* '<NAME>'::
    Rebuild the tree of the selected space from `<NAME>.json` (see *--save-layout*), using the windows that are on the space now, and print `restored <n> of <m> windows`: <m> is the number of windows the file names, <n> the number of them that are on the space. Without a match the tree stays as it is and the command fails. The space must be in tree layout. +
    NAME is checked like *--save-layout* does. A file that cannot be read, or is not a version 1 layout (with the reason and the path), fails before the tree is touched. +
    Each window of the file is matched with a window of the space of the same application (the bundle id, or the application name when one of them has none). The best match is taken first: an exact title, then the longest common title prefix, then the same role and subrole; each window is used once. A window of the file without a match is dropped, and a container left empty or with one child collapses, so the matched windows fill the layout with their shares normalized. +
    The windows of the space that match nothing are added after the focused window, in tree order, without taking focus. Version 1 has no placeholders: a window that opens after the restore is not placed by the file, it gets the usual place of a new window. +
    The restore is a tree command, so *--undo* brings back the tree from before it.

*--padding* 'abs|rel:<top>:<bottom>:<left>:<right>'::
    Padding added at the sides of the selected space.

*--gap* 'abs|rel:<gap>'::
    Size of the gap that separates windows on the selected space.

*--toggle* 'padding|gap|mission-control|show-desktop'::
    Toggle space setting on or off for the selected space.

*--layout* 'tree|float'::
    Set the layout of the selected space. A space that already has the layout keeps its windows and tree.

*--label* ['<LABEL>']::
    Label the selected space, allowing that label to be used as an alias in commands that take a `SPACE_SEL` parameter. +
    If the command is called without an argument it will try to remove a previously assigned label. +
    A pin follows its label: moving the label to another space moves the pin with it, and removing the label or replacing it with another one removes the pin.

*--pin* ['<DISPLAY_SEL>']::
    Pin the selected space to the given display, so that it returns to that display whenever the display is connected. The space must have a label, otherwise the command fails. +
    A direction, 'prev' and 'next' are measured from the display of a space selected by a 'SPACE_SEL', as for *--display*. +
    The pin is kept by the uuid of the display and in memory only: the *yabai.toml* sets it again at startup. A pin moves its space when it is set, when a display is added, removed or moved, and at startup. A space that is moved by hand to another display stays there until one of these happens. +
    A pin to a display that is not connected leaves its space where it is, and so does a pin whose space is the last user space of its display. Without an argument, the command removes the pin of the selected space. +
    The query key *pinned-display* of a space is the arrangement index of the display the space is pinned to, and 0 when it has no pin or its display is not connected. +
    Moving a space needs the scripting addition: without it, the daemon logs one notice and leaves the spaces where they are. System Integrity Protection must be partially disabled.

Window
~~~~~~

General Syntax
^^^^^^^^^^^^^^

yabai -m window ['<WINDOW_SEL>'] '<COMMAND>'

COMMAND
^^^^^^^

*--focus* ['<WINDOW_SEL>']::
    Focus the given window. +
    If none specified, focus the selected window instead. +
    A direction moves focus like i3's 'focus left|right|up|down': it walks up to the closest container laid out in that direction (tabbed counts as side by side) and focuses the neighbouring child, entering it at the window focused there last. At the edge of the space it focuses the display in that direction, otherwise *focus_wrapping* applies. Focus enters that display like sway does: at a window zoomed to the whole space, else, when the tree of its space is laid out in the direction, at the child on the near side (the first one moving east or south, the last one moving west or north), else at the window focused there last. +
    From a window zoomed to the whole space (*--toggle zoom-fullscreen*), a direction skips the windows it covers and focuses the display in that direction, like a fullscreen container in sway; it fails when there is none and does not wrap. *zoom-parent* does not change focus. +
    Without a focused window in a tree, a direction still moves focus: with no focused window (an empty space), or with one yabai could not manage (a system dialog), it focuses the display in that direction from the focused display, entered as above. On a *float* space it focuses the nearest window in that direction on the space, and the display in that direction when there is none. It fails when there is no display in that direction, or that display shows a macOS fullscreen space, as at the edge of a tree; it does not wrap. So one binding, e.g. `yabai -m window --focus east`, moves across windows and displays. +
    From a floating window on any other space, focus moves among the floating windows of that space like sway's floating focus and never to another display: it focuses the floating window whose center lies nearest in that direction, measured along the direction only. With *focus_wrapping* other than 'off' and none that way, it focuses the floating window farthest the other way. It fails when there is no other floating window. +
    'parent' and 'child' select the container around the focused window, or go back down, like i3's 'focus parent|child'. The selected container is outlined, and *--warp* and *--layout* act on it until focus changes.

*--close* ['<WINDOW_SEL>']::
    Close the given window. +
    If none specified, close the selected window instead. +
    Only works on windows that provide a close button in its titlebar.

*--minimize* ['<WINDOW_SEL>']::
    Minimize the given window. +
    If none specified, minimize the selected window instead. +
    Only works on windows that provide a minimize button in its titlebar.

*--deminimize* '<WINDOW_SEL>'::
    Restore the given window if it is minimized. +
    The window will only get focus if the owning application has focus. +
    Note that you can also '--focus' a minimized window to restore it as the focused window.

*--display* '<DISPLAY_SEL>'::
    Send the selected window to the given display. +
    A direction, 'prev' and 'next' are measured from the display of a window selected by a 'WINDOW_SEL', like sway's 'move container to output <dir>', and from the active display for the focused window. +
    On a *tree* space it is added right after the window focused last there, in that window's container (a tab after the focused tab), without *tree_autotiling*; a split set with *--insert* still applies. +
    When the selected window had focus, focus stays on its old space, at the window focused last there.

*--space* '<SPACE_SEL>'::
    Send the selected window to the given space, placed and with focus as for *--display*. 'prev' and 'next' are measured from the active space, also for a selected window, like sway's 'move container to workspace next|prev'.

*--swap* '<WINDOW_SEL>'::
    Swap position of the selected window and the given window. +
    When one of the two has focus and they are on different spaces, focus goes to the other one, which now takes its place, so focus stays on the same space and display, like sway; on the same space the focused window keeps focus. A window swapped in for the active tab of a tabbed container becomes the active tab. The same holds for a window dropped on the center of another with *mouse_drop_action* 'swap'.

*--warp* '<WINDOW_SEL>'::
    A direction moves the window (or the selected container) like i3's 'move left|right|up|down': it swaps with a neighbouring window, moves into a neighbouring container, or leaves its container at the edge. If no container is laid out in that direction, the space is re-oriented along it and the window is placed first (moving west or north) or last (moving east or south), next to the rest of the space, even when there is a display that way, like sway: `--warp west` from the top window of a vertical space of two windows lays them out side by side. Only a move along the layout of the space at its edge, or of the only window of the space or of a container at its edge, goes to the display in that direction, as a whole: a container keeps its structure and arrives on the side it comes from, like sway: first (moving east or south) or last (moving west or north) when that space is laid out in the direction, otherwise in the first container laid out in the direction along the windows focused there last (tabbed counts as side by side), first or last in the same way, or, when there is none, next to the window focused there last, before it moving east or south and after it moving west or north. +
    A window zoomed to the whole space (*--toggle zoom-fullscreen*) does not move within its space: a direction moves it to the display in that direction, like a fullscreen container in sway. It is added last to that space's tree and stays zoomed, and a window zoomed to the whole space there is unzoomed. It fails when there is no display in that direction. *zoom-parent* does not change the move. +
    A direction moves a window outside a tree (a floating window, one not tiled yet, one on a *float* space, or one yabai could not manage) to the current space of the display in that direction from its own display, like *--display*, and it stays focused. A floating window stays floating; a window that yabai tiles there (one from a *float* space, or one not tiled yet) arrives on the side it comes from, like a container moved in the tree, so *--warp* the other way sends it back. It fails when there is no display in that direction, or that display shows a macOS fullscreen space; it does not wrap. So one binding, e.g. `yabai -m window --warp east`, moves tiled windows in the tree and every other window across displays. sway differs here: its 'move left|right|up|down' moves a floating window by 10 pixels, and the window changes output only when its center crosses to another one. +
    A window selector places the window right after that window, in its container.

*--stack* '<WINDOW_SEL>'::
    The given window becomes a tab next to the selected window, which is wrapped in a tabbed container first if it is not a tab yet.

*--layout* 'tabbed|split|toggle|splith|splitv|toggle-split'::
    Change the layout around the selected window, like the *layout* command of i3. +
    The layout of the container that holds the selected window (or the selected container) changes: 'tabbed', 'splith' and 'splitv' set it, 'split' returns to its last split layout, 'toggle' switches between tabbed and the last split layout, and 'toggle-split' switches between 'splith' and 'splitv'. A window directly on the space is wrapped in a new tabbed container first, since the space itself is always split. A container that holds nothing but the selected window, inside a container that holds nothing else, is closed first, like i3, so that switching a single tab between split and tabbed does not nest containers.

*--split* 'horizontal|vertical|toggle'::
    Like i3's 'split h|v|toggle'. Wraps the selected window in a new container laid out side by side ('horizontal') or on top of each other ('vertical'), so the next window opens next to it inside that container. If the window is the only child of its container, the orientation of the container changes instead. 'toggle' picks the orientation that the container of the window does not have.

*--insert* '<DIR_SEL>|stack'::
    Set the splitting mode of the selected window. +
    If the current splitting mode matches the selected mode, the action will be undone. +
    The next window opens on that side of the selected window, splitting it if its container is laid out the other way, or as a tab next to it with 'stack'.

*--grid* '<rows>:<cols>:<start-x>:<start-y>:<width>:<height>'::
    Set the frame of the selected window based on a self-defined grid. +
    The grid covers the area of the display inside the configured padding and gap of its visible space, regardless of 'auto_padding'.

*--move* 'abs|rel:<dx>:<dy>'::
    If type is 'rel' the selected window is moved by 'dx' pixels horizontally and 'dy' pixels vertically. +
    If type is 'abs' 'dx' and 'dy' will become the new position.

*--resize* 'top|left|bottom|right|top_left|top_right|bottom_right|bottom_left|abs:<dx>:<dy>'::
    Resize the selected window by moving the given handle 'dx' pixels horizontally and 'dy' pixels vertically. +
    If handle is 'abs' the new size will be 'dx' width and 'dy' height and cannot be used on managed windows.

*--ratio* 'rel|abs:<dr>'::
    Change the share of the selected window (or the selected container) in its container, like i3's 'percent'. +
    If type is 'rel' the share is changed by 'dr', otherwise 'dr' becomes the new share. The space is taken from or given to the next container, or the previous one for the last container.

*--toggle* 'float|sticky|pip|shadow|split|zoom-parent|zoom-fullscreen|windowed-fullscreen|native-fullscreen|expose|<LABEL>'::
    Toggle the given property of the selected window. +
    The following properties require System Integrity Protection to be partially disabled: sticky, pip, shadow, LABEL (scratchpad identifier) . +
    Toggling a scratchpad by 'LABEL' shows it on the active space, moving it there if necessary, or hides it if it is already shown there. See the config options *scratchpad_exclusive*, *scratchpad_raise*, *scratchpad_below* and *scratchpad_grid*. +
    A window that floats again returns to the frame it had the last time it was floating (moved or resized while floating, or tiled again). That frame is kept when at least half of its area is on a display; otherwise the window is centered at its current size on its display. A window that has never floated keeps its tiled frame when it floats.

*--sub-layer* '<LAYER>'::
    Set the stacking sub-layer of the selected window. +
    The window will no longer be eligible for automatic change in sub-layer when managed/unmanaged. +
    Specify the value 'auto' to reset back to normal and make it become automatically managed. +
    System Integrity Protection must be partially disabled.

*--opacity* '<FLOAT_SEL>'::
    Set the opacity of the selected window. +
    The window will no longer be eligible for automatic change in opacity upon focus change. +
    Specify the value '0.0' to reset back to full opacity and make it become automatically managed. +
    System Integrity Protection must be partially disabled.

*--raise* ['<WINDOW_SEL>']::
    Orders the selected window above the given window, or to the front within its layer. +
    System Integrity Protection must be partially disabled.

*--lower* ['<WINDOW_SEL>']::
    Orders the selected window below the given window, or to the back within its layer. +
    System Integrity Protection must be partially disabled.

*--label* ['<LABEL>']::
    Label the selected window, allowing that label to be used as a `WINDOW_SEL` parameter, e.g. `yabai -m window --label term`, then `yabai -m window --focus term`. +
    A label names one window: labelling another window moves it there, and labelling a window again replaces its label. +
    If the command is called without an argument it will try to remove the label of the window. +
    A window label and a scratchpad (*--scratchpad*) may have the same name: they are separate namespaces. +
    A label cannot be a window selector word (such as `north`, `prev`, `largest` or `parent`), a command name or a `stack.<index>`. +
    The label of a window is reported by *query --windows* as `label`.

*--scratchpad* ['<LABEL>|recover']::
    Unique identifier used to identify a window scratchpad. +
    An identifier may only be assigned to a single window at any given time. +
    A scratchpad window will automatically be treated as a (manage=off) floating window. +
    If the scratchpad is already taken by another window, this assignment will fail. +
    If the scratchpad is re-assigned, the previous identifier will become available. +
    If no value is given, the window will seize to be a scratchpad window. +
    The special value 'recover' can be used to forcefully bring all scratchpad windows to the front. +
    This can be useful if windows become inaccessible due to a restart or crash. +
    System Integrity Protection must be partially disabled.

Query

Rule
~~~~

All rules that match the given filter will be applied in the order they were registered. +
If multiple rules specify a value for the same property, the latter rule will end up overriding that value. +
If the display and space properties are both set, the space property will take precedence. +
The following properties require System Integrity Protection to be partially disabled: sticky, sub-layer, opacity, scratchpad.

General Syntax
^^^^^^^^^^^^^^

yabai -m rule '<COMMAND>'

COMMAND
^^^^^^^

*--add [--one-shot] ['<ARGUMENT>']*::
    Add a new rule. Rules apply to windows that spawn after said rule has been added. +
    If '--one-shot' is present it will apply once and automatically remove itself. +
    A rule with the *label* of an existing rule replaces that rule at its index.

*--apply ['<RULE_SEL>' | '<ARGUMENT>']*::
    Apply a rule to currently known windows. +
    If no argument is given, all existing rules will apply. +
    If an index or label is given, that particular rule will apply. +
    Arguments can also be provided directly, just like in the *--add* command. +
    Existing `--one-shot` rules that have yet to apply will be ignored by this command.

*--remove '<RULE_SEL>'*::
    Remove an existing rule with the given index or label. The rules after it move up one index and keep their order.

*--list*::
    Output list of registered rules.

ARGUMENT
^^^^^^^^

*label='<LABEL>'*::
    Label used to identify the rule with a unique name

*app[!]='<REGEX>'*::
    Name of application. If '!' is present, invert the match.

*title[!]='<REGEX>'*::
    Title of window. If '!' is present, invert the match.

*role[!]='<REGEX>'*::
    https://developer.apple.com/documentation/applicationservices/carbon_accessibility/roles?language=objc[Accessibility role of window]. If '!' is present, invert the match.

*subrole[!]='<REGEX>'*::
    https://developer.apple.com/documentation/applicationservices/carbon_accessibility/subroles?language=objc[Accessibility subrole of window]. If '!' is present, invert the match.

*display='[^]<DISPLAY_SEL>'*::
    Send window to display. If '^' is present, follow focus.

*space='[^]<SPACE_SEL>'*::
    Send window to space. If '^' is present, follow focus.

*manage='<BOOL_SEL>'*::
    Window should be managed (tile vs float). +
    Most windows will be managed automatically, so this should mainly be used to make a window float.

*sticky='<BOOL_SEL>'*::
    Window appears on all spaces. +
    System Integrity Protection must be partially disabled.

*mouse_follows_focus='<BOOL_SEL>'*::
    When focus goes to the window from another display, put the mouse at its center. Overrides the global *mouse_follows_focus* setting.

*sub-layer='<LAYER>'*::
    Window is ordered within the given stacking sub-layer. +
    The window will no longer be eligible for automatic change in sub-layer when managed/unmanaged. +
    Specify the value 'auto' to reset back to normal and make it become automatically managed. +
    System Integrity Protection must be partially disabled.

*opacity='<FLOAT_SEL>'*::
    Set window opacity. +
    The window will no longer be eligible for automatic change in opacity upon focus change. +
    Specify the value '0.0' to reset back to full opacity and make it become automatically managed. +
    System Integrity Protection must be partially disabled.

*native-fullscreen='<BOOL_SEL>'*::
    Window should enter native macOS fullscreen mode.

*grid='<rows>:<cols>:<start-x>:<start-y>:<width>:<height>'*::
    Set window frame based on a self-defined grid.

*scratchpad='<LABEL>'*::
    Unique identifier used to identify a window scratchpad. +
    An identifier may only be assigned to a single window at any given time. +
    A scratchpad window will automatically be treated as a (manage=off) floating window. +
    If this rule matches multiple windows, only the first window that matched will be assigned this scratchpad identifier. +
    System Integrity Protection must be partially disabled.

*insert='<DIR_SEL>|stack'*::
    Place a new window as *window --insert* does: next to the focused window of the tree on the given side, or as a tab of its tabbed container with *stack*. +
    It applies to windows created while yabai runs, at the moment they are first tiled. It does not apply to windows that exist when yabai starts, to *rule --apply*, or to windows tiled later (for example after *window --toggle float*). +
    It replaces a pending *window --insert* in that view. +
    It takes precedence over *tree_autotiling*, and has no effect on a window with (manage=off).

Batch
~~~~~

yabai -m batch::
    Run several commands in one message, with one round trip to the daemon. The commands are read from stdin, one per line, and each line holds the words that follow `yabai -m`, e.g. `window --focus east`. A line that starts with `yabai -m` (or `yabai --message`) has that prefix removed. +
    Words follow the quoting of sh: single and double quotes and backslash escapes, and `''` is an empty argument. Blank lines and lines that start with `#` are skipped. A line is not run by a shell, so a line that a shell would compute is an error and nothing is sent: `$VARIABLE`, `$(...)`, backticks, `;`, `&`, `|`, `<`, `>`, parentheses, globs (`*`, `?`, `[`), a leading `~`, and an unquoted reserved word such as `if`, `then`, `fi`, `while`, `done` or `{` at the start of a line. An unterminated quote and a line with no command are errors too. Each error names its line, e.g. `yabai-msg: batch: line 3: dynamic shell, nothing sent`. +
    The commands run in order, each as a message of its own: a command that fails does not stop the others, and a batch cannot contain a batch. *config --check* does not check the commands of a batch; they are checked when the batch runs. +
+
----
yabai -m batch <<'EOF'
config window_gap 6
config top_padding 12
window --focus east
EOF
----
+
The output of a batch is the output of its commands in order, such as the value of a query. A failing command writes its failure with its index in front, where 1 is the first command of the batch. The index counts commands, not lines of stdin: blank and comment lines are not counted. The response fails, and *yabai -m* exits with status 1, when any command failed. A failing response is printed on stderr in full, so the output of the commands that succeeded goes to stderr too. +
A batch with no command, e.g. stdin with only blank lines, fails with `batch: no commands given`. `yabai -m batch` takes no arguments: with any, it fails and sends nothing. A batch is one message, so it is limited to 1 MiB like any message.

Subscribe
~~~~~~~~~

yabai -m subscribe [<EVENT>...]::
    Stream events to the client, one JSON line per event, until the daemon or the client ends the subscription. The events are the names of *signal --add*, e.g. `yabai -m subscribe window_focused space_changed`; without an event, every event is streamed. +
    The first line lists the subscribed events, in the order of the EVENT list under *Signal*, e.g. `{"subscribed":["space_changed","window_focused"]}`. +
    Each later line is one event: its name as *event*, then the environment values of the event as keys in lowercase, without the *YABAI_* prefix, e.g. `{"event":"window_focused","window_id":"42"}`. The keys are sorted and every value is a string. The line ends with a newline. +
    The client prints each line as it arrives and exits with status 0 when the daemon closes the connection. An unknown event fails with the events it accepts, and the client exits with status 1, as for any failure. +
    The events are not filtered by the *app* and *title* filters of a signal; every event of the subscribed type is streamed. A subscription keeps its connection open, so it cannot be a command of a batch, and *config --check* does not run it. +
    A subscriber that does not read is dropped when more than 1 MiB of its events are waiting to be written, or when a write waits more than 5 seconds; the daemon then closes its connection. A closed client is noticed when the next event is written. Other subscribers and the window manager are not affected.

Tree Layout
-----------

'tree' is the tiling layout of every space that does not use 'float'. It arranges windows like i3 and sway do. Every window is a leaf in a tree of containers, and the space itself is the root container. +
A container lays out any number of children in one of three ways: 'splith' (side by side), 'splitv' (on top of each other) or 'tabbed' (one child visible at a time, with a row of tabs on top). +
Each container remembers which of its children was focused last.

A new window opens right after the focused window, inside the same container. While a container is selected with *window --focus parent*, it opens right after that container instead, like i3 and sway. With *tree_autotiling*, the focused window is first split along its longer side. +
When the last window of a container closes, the container is removed as well. +
Containers that would only nest a split inside a split of the other orientation are flattened again.

Tabbed containers draw a tab bar with the *tab_bar_\** settings, also when they hold a single tab. +
A tab that holds a container is titled with its layout and applications, e.g. 'H[iTerm2 Safari]'. +
The windows of hidden tabs keep the frame of the container and are ordered below the active tab. This needs the scripting addition when a tab holds more than one window.

Sizes are shares of the parent container, like i3's 'percent'. *window --resize* moves an edge of the window, taking the space from or giving it to the neighbour on the other side of that edge in the closest container laid out in that direction, and *window --ratio* sets the share of the window in its container. Dragging with *mouse_action2* 'resize' does the same, and with *mouse_drag_split* 'on' a plain drag on the gap between two tiled windows does too. *window --toggle split* toggles between 'splith' and 'splitv', *window --toggle zoom-fullscreen* and *zoom-parent* make the window cover the space or its container, and *space --balance*, *--rotate* and *--mirror* work on the whole tree. +
In *query --windows*, 'split-type' is the layout of the container of the window ('vertical' for 'splith', 'horizontal' for 'splitv', and 'none' for tabbed), 'stack-index' is the position of its tab in the closest tabbed container +
Dropping a window dragged with the mouse onto the edge of another window places it on that side of the window, and dropping it on the center swaps the windows, or makes it a tab of the other window with *mouse_drop_action* 'stack'. *mouse_drop_preview* 'ghost' shows a translucent copy of the dragged window where it would land while the drag is in progress.

When the focused window closes, the window focused before it in the same container gets focus, so closing a tab shows the previous tab. +
The 'stack.prev', 'stack.next', 'stack.first', 'stack.last', 'stack.recent' and 'stack.<index>' selectors pick tabs of the closest tabbed container, and 'prev', 'next', 'first' and 'last' follow the order of the tree.
